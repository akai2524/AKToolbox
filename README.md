# AK工具箱

面向小米澎湃系统的 LSPosed 模块，最低安装版本为 Android 15。主要实现依据以下实机环境，其他机型和系统版本的功能效果尚未验证：

当前开发版：0.2.0（38）。新增背屏乘车码支持（支持支付宝与微信乘车码小程序、公交/地铁乘车码无缝切换、紧凑正方形单码大二维码展示与摄像头避让），支持支付宝首页与桌面快捷方式无缝显示付款码。0.1.21 保持 0.1.20 的微信二维码尺寸，并将其上移约 40 像素；实际位置及扫码效果需自行验证。背屏付款码默认关闭，通过 Hook 微信、支付宝与背屏进程显示付款码，不要求工具箱持续在后台运行。实验版已在本机验证两个应用的背屏显示和摄像头避让；完整生命周期与实际扫码仍需实机验证。0.1.16 将 Google 服务磁贴改为等待实际状态变化，由控制中心处理顶部提示；0.1.17 已彻底移除 5G 磁贴与双卡网络模式锁定逻辑，不再需要“电话服务”作用域。输入法和耳机音效的历史验证记录针对对应版本，不代表新版已完成全部实机验证。

0.2.0 新增背屏乘车码支持（独立开关：乘车码自动显示到背屏），适配支付宝出行（公交/地铁码动态切换）与微信乘车码小程序；优化背屏单码紧凑正方形展示布局；重构支付宝付款码识别算法，全面支持从支付宝首页直接进入付款码及桌面快捷方式进入。

0.1.32 增加屏幕时间显示过滤：在工具箱内选择应用并开启隐藏，在 LSPosed 勾选“小米设置”作用域，再强行停止小米设置或重启手机。更改选择或关闭开关后同样需要重启该进程以刷新其缓存；旧的独立 `com.cleaner.screentimehook` 模块应保持关闭。默认不选择任何应用，系统应用默认不显示，可在列表中开启显示。

0.1.33 优化应用选择界面，并在当前搜索和系统应用筛选条件下，将已选择的应用排在列表前面。

0.1.34 调整应用列表四周和项目之间的间距。

0.1.35 移除截图、系统界面、小米音效和背屏付款码相关组件的固定应用版本号限制，尝试加载现有功能；不同版本的内部接口可能变化，实际效果需实机验证。截屏组件 RELEASE-1.6.3.44 / 10603044 的截图与复制入口已静态核对。

0.1.36 将最低安装版本调整为 Android 15，并移除背屏付款码单独的机型和 Android 版本判断。其他机型的背屏组件、显示屏编号、窗口权限及布局可能不同，实际效果需实机验证。

此功能只拦截小米设置进程读取的统计和事件，不直接删除系统底层使用记录。小米设置可能基于过滤后的结果更新自己的缓存，关闭隐藏后历史统计何时重新显示取决于小米自身的数据处理；不能保证全部系统版本的图表和汇总都受影响。该功能尚未实机验证。

## 首版功能

- Google服务磁贴：使用加粗的谷歌 G 图标，以高亮 / 暗色和“已开启 / 已关闭”区分状态；仅切换原生名单中的 Google 核心服务与商店。
- 第三方输入法全面屏优化：对勾选作用域的第三方输入法启用系统原有的小米全面屏键盘底部栏。
- 底部栏输入法列表：显示已启用的输入法，并保留“键盘设置”入口。
- 耳机音效自动切换：耳机连接时选择原声，最后一副耳机断开后选择杜比全景声；空间音频设置保持原样。
- 普通截图和长截图自动复制图片，保留正常保存的截图文件。
- 截图时隐藏状态栏内容，保留图片尺寸、顶部背景，截完恢复。
- 仅在通知中心日期旁显示小米天气的天气、温度与可选城市，控制中心不显示。
- 隐藏控制中心编辑按钮。
- 重启系统界面：位于通知与控制中心设置下方，用于应用相关界面设置。

界面功能有独立开关。全新安装时默认启用所请求的界面功能，升级时保留已有设置。

## 背屏付款码

作用域勾选背屏、微信和支付宝，并重启这些进程。实现依据本机背屏组件 426091419、微信 8.0.79（3200）和支付宝 12.12.36.7600（212363）；其他版本也会尝试加载，但页面和内部接口变化可能导致失效。付款页面可见时，应用进程将码图通过验证发送方身份的本机广播传给背屏进程；不读取码字符串、不存储图片。背屏窗口使用防截屏标志，页面退出、锁屏或码图超时后清除。支付宝的安全遮罩或风险提示会阻止显示。

新方案不再为付款码功能配置工具箱后台策略。升级后首次打开工具箱时，会尝试恢复旧版保存的后台设置：只恢复仍保持旧版设置值的项目，失败时保留记录并可重试。

早期版本若未记录自动修改前的设置，本版本无法推断或恢复那些原值，需要手动检查。若在工具箱设置后手动把某项改为其他值，恢复时会保留该值。AppOps 不支持原子比较更新，因此并发修改时无法保证识别每一次竞争。

## Google服务行为

已通过 ADB 对比原生 Google 基础服务开关：关闭后，本机实际停用 GMS、GSF、Play 商店、ConfigUpdater、ExtShared 和打印推荐六个已安装组件，并停止核心进程。模块沿用原生组件名单与禁用状态 2，不宣称比同等组件范围的原生开关更省电。

每次首次关闭前，先持久化核心组件原启用状态；开启时恢复记录中的精确状态。切换失败时尝试回滚，并保留未完成的恢复记录。没有模块记录、但系统原生开关已关闭时，开启操作按原生启用状态恢复核心服务。

0.1.5 已移除“跟随 GApps 开关”的界面和切换逻辑。升级时仅按旧版恢复记录，将曾被跟随停用的 Google、Gemini 等应用恢复原启用状态，并清理对应记录；核心服务保持当前状态。若这些应用已被手动改为其他启用状态，则保留手动修改。以后切换 Google服务不再更改这些应用。

不按 `com.google.*` 前缀批量停用。WebView、文档选择器、输入法、网络资源与系统模块不在名单内。仅操作当前系统界面所在的主用户，不操作双开空间或其他用户。

Google服务磁贴按点击、面板监听和相关应用状态变化刷新；天气订阅小米天气内容更新。没有周期性轮询、后台保活服务或定时唤醒任务。实际待机耗电仍需在设备上对照观察。

设置页的“添加Google服务磁贴”由已启用的系统界面模块直接添加，无需再次确认；若模块未连接，会提示失败。

点击 Google 服务磁贴后，先保留原状态，直到实际切换完成再更新；正常的开关状态变化交由澎湃控制中心显示顶部提示。切换失败仍会显示错误提示。关闭面板或状态未发生变化时，系统可能不显示顶部提示。

## 双卡网络模式

0.1.14 移除工具箱的 5G 磁贴，不再提供该磁贴的添加、状态监听和切换操作；两张卡当前的网络设置不会因此被主动更改。以下独立的双卡网络模式保持逻辑仍然保留。

在这台手机上发现系统切换默认上网卡时会按云端策略把另一张卡的 4G 模式改为 5G。0.1.7 在电话服务计算网络模式时保留两卡各自的原模式，仅在两张实体卡均可用、原模式仍在系统支持列表中时介入；不使用切换后再次改回的方式。实机检查了卡一、卡二分别为 4G 时来回切换上网卡的情况，电话服务记录中对应卡始终请求 4G。系统仍会正常处理上网卡切换，网络可能暂时重连。

## 耳机音效行为

启用后，系统识别到有线或蓝牙耳机时选择原声，最后一副耳机断开时选择杜比全景声；空间音频设置不由本功能修改。启用时若尚无耳机，不改变当前扬声器音效。功能通过系统音频设备变化回调运行，不新增周期性轮询。

蓝牙设备须由系统报告为耳机类型，模块据此排除音箱和车载设备；无法确认类型的设备会跳过。设备类型若被系统误报，识别结果也可能受影响。有线设备须由系统识别为有线耳机或 USB 耳机；有线耳机、蓝牙音箱和车载设备尚未实机检查。

## 输入法

功能沿用小米的底部栏和系统全面屏键盘设置，模块负责解除第三方输入法限制，并处理适配新版本 Android 的输入法可能出现的底部重复留白。修改工具箱内的功能开关后，需要重新启动对应输入法进程。

在 LSPosed 中对每个需要使用该功能的第三方输入法勾选作用域，例如微信输入法和讯飞输入法；以后安装其他输入法也需将其加入作用域。模块会识别作用域内的输入法，不对普通应用或本机已支持的小米定制输入法启用此功能。系统全面屏键盘优化的原有开关仍由系统控制。

“底部栏显示所有已启用输入法”是独立开关。需要在 LSPosed 勾选要使用底部栏的输入法，包括搜狗输入法小米版；更改开关或作用域后重启对应输入法进程。切换列表依赖系统界面作用域已加载：系统界面只接受当前输入法发出的请求，且仅允许切换到已启用的输入法。无需为此功能勾选系统框架作用域。

输入法列表和切换请求通过异步回调处理，等待系统界面时不阻塞输入法主线程；请求超时或失败时提示重试，超时后的迟到列表不会重新弹窗，系统界面会拒绝已过期的切换请求。每次打开列表都重新获取已启用输入法，不新增周期性轮询。

## 安装与启用

1. 安装构建的 APK。
2. 在 LSPosed 中启用模块，勾选“系统界面”“截屏”“电话服务”（`com.android.phone`）和“音质音效”（`com.miui.misound`）；输入法功能另需勾选要使用底部栏的输入法。控制中心插件在系统界面进程加载时适配。
3. 重启手机，使各进程加载对应作用域。
4. 打开AK工具箱，确认模块连接，按需点击“添加Google服务磁贴”。
5. 按需调整设置。界面缓存可能需要重新展开面板或重启系统界面才更新。

控制中心编辑按钮的显隐在面板初始化时决定，修改后可点击“重启系统界面”。重启时屏幕会短暂刷新，系统可能回到锁屏；模块随后自动检查连接。磁贴使用系统标准的面板监听回调刷新状态，无常驻轮询。

卸载或停用模块前，如需恢复 Google 核心服务，可先在工具箱开启 Google服务。模块不删除应用数据。

## 构建与检查

需要 JDK 17、Android SDK 37.0 和 Build Tools 37.0.0。Gradle 9.4.1、AGP 9.2.1。

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug
.\scripts\check-core.ps1
```

APK：`app/build/outputs/apk/debug/app-debug.apk`。

项目包含核心组件与旧版记录迁移检查；这些检查不能替代手机上的 LSPosed 和界面验证。

独立的 `device-checks` 模块仅用于实机测试，不包含在工具箱 APK 中：

```powershell
.\gradlew.bat :deviceChecks:assembleDebug :deviceChecks:lintDebug
```

该测试应用提供无私人信息的滚动页面，检查新截图的图片 MIME、URI 读取与完整解码，并按间隔生成 24 条低优先级测试通知。其清除按钮只移除自身通知。测试完可单独卸载。实机结果见 [验证记录](docs/验证记录.md)。
